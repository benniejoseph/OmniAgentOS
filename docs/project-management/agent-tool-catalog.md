# Agent tools: reuse first, add selectively

Reviewed **6 October 2026 (IST)** against release `70b1522a886383775636377864e378cab08c78a8` and the official sources linked below. This is a source-code inventory and integration recommendation, not a claim that every user's credentials, quotas, or workflows were exercised in production. No provider account was created, paid request made, package installed, or integration enabled for this review.

The best first step is to make the existing tools easier to discover and show their cost/readiness clearly. Asael already implements most requested categories. The useful additions are one cheaper search route, downloadable document formats, and an optional local OCR route. Adding several overlapping MCP servers would increase maintenance without establishing better results.

## Immediate cleanup and cost opportunities

1. **Publish one capability/readiness view.** Use the existing registry and configured model/connector routes to show “available”, “needs connection”, “local device offline”, “quota exhausted” and “not implemented”. Keep provider cost distinct from local compute/storage. This resolves confusion more directly than another tool installation.
2. **Measure before replacing.** Break down existing search, image and OCR calls, failures, retries and unknown-cost rows from the usage ledger. Record the provider request ID, latency and output usefulness. Provider free credits do not remove model synthesis or storage costs.
3. **Make image cost selectable.** Add a provider-supported draft/standard/high-quality choice instead of hardcoding high quality for every OpenAI image. Add a model/version-specific estimator only when the needed pricing inputs exist. Keep actual provider billing and estimates distinct. This is a proposed change; this review did not alter runtime behavior.
4. **Reuse text extraction and PPTX creation.** Preserve parser page/byte/time/concurrency bounds. Do not introduce another PDF parser or paid slide service without a case the current tools cannot handle.
5. **Pilot one basic search adapter.** Keep `web.search` as the public tool. Put provider choice and per-tenant quotas behind the server route, normalize source provenance/citations, and return a clear exhausted-quota result. An automatic fallback to a paid provider must respect an explicit spending policy.

## Small implementation sequence

These are planning estimates for focused engineering and verification, not elapsed time already spent or a commitment to activate every option.

| Order | Bounded deliverable | Rough effort | Completion evidence |
| --- | --- | --- | --- |
| 1 | Capability/readiness and usage-cost inventory in the app | 0.5–1 day | Each implemented tool shows its real configured state; missing renderers are not advertised as ready. |
| 2 | One Tavily search adapter and hard monthly/daily caps | 1–2 days | Governed tenant-scoped search, source normalization, quota exhaustion, timeout and permitted fallback behavior verified with fixtures; small opt-in live comparison after credentials exist. |
| 3 | One first-party DOCX export using the artifact lifecycle | 1–2 days | Private, idempotent, bounded document generation with a download link and rendered sample review. Add XLSX/PDF as separate slices after usage justifies them. |
| 4 | Image draft quality and cost visibility | 0.5–1 day | Supported quality reaches the provider; unknown pricing stays explicit; the existing asset lineage and idempotency remain intact. |
| 5 | Optional OCR or Cloudflare image pilot | 1–2 days each | Accuracy/quality and end-to-end cost measured on a small representative fixture set before changing defaults. |

First finish the operational baseline and decide which single output/workflow users need most. Keep the rest in the backlog; adding every listed service would contradict the cleanup goal.

## Integration requirements

- Reuse the governed executor and canonical tool IDs. Provider-specific adapters must not acquire tenant authority from untrusted remote metadata.
- Keep keys server-side in the existing credential store. Send only task-required public queries or authorized documents to a new provider; account-level privacy and retention terms must be checked before private data is enabled.
- Meter calls even when the provider charge is zero. Track free-tier consumption separately from USD, including retries, failed calls and provider-wide shared allowances.
- Bound request count, pages, bytes, tokens, duration and concurrency. Exhausted quotas must return an actionable status rather than a retry loop or hidden paid fallback.
- Keep public-web cache entries free of private queries/content; otherwise scope cache identity to tenant/actor. Record retrieval time and expiration so savings do not silently degrade freshness.
- Save generated outputs through the current private artifact/asset lifecycle with lineage, checksums, retention and idempotency. Return links, not giant binary tool responses.
- Pin only the dependencies needed by the next slice. Local PDF/OCR/browser workloads need measured worker memory/CPU limits; free software can still increase Fly/Vercel bills.
- Tools installed for Codex or Claude development are not automatically available inside Asael. Product integration still needs a contract, readiness UI, scope enforcement and release evidence.
