# Native Markets workspace

The native workspace exposes Overview, Events, Technical, Backtests and Journal over the existing governed Market services. Instrument identities, source times, exact snapshot IDs, detector candidates, experiment manifests, sealed forecasts and outcomes remain visible. Descriptive baselines are capped at 500 stored replays; journal metrics describe the returned window. Neither is presented as a predictive probability or live trading advice.

Opening the workspace reads the overview and at most 20 stored snapshot metadata rows. Stored snapshot selection uses an exact owner-scoped GET and never fetches a provider. Fetch provider snapshot and Fetch official calendar are explicit user actions. Empty successful reads, missing storage, failed source reads and unavailable calendar sources remain distinct.

The native repository admits operations only when the generated publication supports them and the current canonical user, request actor, tenant, role and API agree. Reads use a fresh same-API bootstrap; mutations use the existing exact-token authorized transport. Provider invalidation and repository disposal are checked after the authority probe as well as before it. Hidden or locked views stop reads and hide private inspectors. The legacy MarketsView constructor is a compatibility wrapper around the current provider boundary.

Existing enrolled actions remain available: official history import, replay build, retrospective backtest, daily/weekly forecast generation and scoring up to two due forecasts. Each requires an explicit exact-request review. Before dispatch, the immutable body and idempotency key are stored through the shared encrypted compare-and-swap recovery broker, under an exact owner/API binding. Accepted receipts survive an independent refresh failure. A lost response or uncertain protected save blocks fresh actions across view disposal and app restart. Reading evidence or refreshing a known job never resubmits it. The server currently has no public lookup by an unknown job's request key; the workspace therefore retains that decision for inspection rather than pretending a read reconciled it.

Saved browser analysis appears as bounded metadata. Its opaque chart plugin state is removed in SQL. Native chart-state editing/generation, provider configuration, arbitrary URL opening and trading are not enrolled here. Source URLs remain inspectable data. Price rendering reuses the existing closing-price canvas; the exact snapshot inspector exposes OHLC records and all source metadata.

No migration is required. Publication v34 provides the typed reads, stored snapshot paths, metadata view, Market job GET and calendar. Native shared integration needs the Markets recovery namespace in both Dart and Swift and the current NativeMarketsView router entry; the root release lane owns those shared files. Focused schema, admission, uncertainty and responsive tests were authored in this slice; execution belongs to the serial release lane.
